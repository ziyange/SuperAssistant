# ADR-009：开发记录按成果和问题收敛

- 状态：Accepted；用户于 2026-11-27 批准迁移。
- 替代范围：仅替代 ADR-005 中“runtime trace and permission audit records bind each write”的开发逐操作记账要求；ADR-005 的明确授权、精确文件范围、迭代边界和阶段接力仍有效。

## 背景

已安装的文档优先 skill v3.1.0 默认按独立验收成果保留一份记录，Strict 不自动启用事务日志。但本仓库旧门禁仍强制对每次修改追加 Intent/Result，再重复更新任务证据，造成维护噪声。

## 决策

自 TASK-857 起，普通开发不再追加 permission-audit.log、execution-trace.json 或逐操作锁。现有两份日志及 expansions.json 原路径冻结，由 [基线清单](../delivery/logging-baseline.json) 固定哈希、数量与来源；旧校验器仍用于复核历史，失败不能因迁移变为成功。

唯一人工开发记录为 [中文开发记录](../delivery/development-log.md)：新错误登记或归并到同一问题，独立可验收成果记录一次；普通读取、修改、成功命令及重复重试不写流水。Task Pack 在开工、范围调整和收尾时更新，收尾链接到该记录。工程事实变更仍同步写入其权威文档，不复制开发过程。

本地与 CI 使用相同的新记录门禁，检查历史冻结、记录结构、真实 Git 文件范围与任务授权。结构校验不证明功能正确，验收仍须实际测试。应用自身的授权、Attempt、Decision、安全事件及不可变产品审计完全不变。

旧历史分组器兼容任务首个文件写入之前的 MODE_SWITCH：它是全局控制事务，不是任务起始锚点。事务不从输入移除，完整哈希链、配对和状态仍交给原运行轨迹校验器检查；控制事务不能伪装成文件路径，后续作用域仍以已提交的 Task Pack 写入为起点。这是对原分组器误报的修复，不是豁免审计失败。

## 后果与边界

保留历史英文原始证据，不逐条翻译或重写；人工新增说明必须中文，命令和固定标识保留原文。历史缺口、耗尽的迭代及阻断继续有效。本决策不授权删除工作树、扩大应用权限、合并、推送或发布。基线清单在后续提交中不可悄悄重置；其他工作树不自动迁移。
